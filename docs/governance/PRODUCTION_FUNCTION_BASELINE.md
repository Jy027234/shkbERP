# 上海凯奔 ERP 现网业务功能基线

> 快照日期：2026-08-16。来源是经授权登录 `http://101.43.50.30:8000` 后，对可见菜单、列表页、真实数据和只读操作入口的核对；未执行新增、审核、删除、SQL、上传、部署或服务器配置修改。

## 用途与边界

本文件定义上海凯奔当前产品的**业务范围**。`shkbERP` 仍是唯一开发和发布源码，候选标签、迁移和本地验证仍以源码治理文件为准；但通用源码、旧页面或半成品不能仅因存在于仓库就被当作上海凯奔业务需求。

现网菜单与页面用于决定“应当补齐什么”；它们不会自动覆盖源码实现、发布版本或数据库迁移。出现差异时，先记录差异，再在本地隔离环境完成契约、schema、测试和候选验证。

## 明确排除与命名校正

- 线上没有“销售管理”或销售订单、销售出库、销售退货等业务菜单。仓库中的销售相关通用代码不属于上海凯奔产品范围，保持冻结/非发布范围，除非业务负责人明确启用。
- 线上没有“成品出入库”；该半成品继续冻结，不能补 schema 或纳入核心回归。
- “仓库调拨”是现网库存管理下的子功能，不是缺失功能。
- 现网名称是“线束检测机任务”。源码路由或历史资料中的 `tightening`、 “拧紧机”仅是遗留内部命名，不能作为用户界面或业务术语。

## 人事模块本地替代进展（2026-08-16）

人事模块已确认是正式业务范围，且线上具有真实列表数据与员工、证书、培训、授权相关操作入口。本轮已在唯一源码仓库补齐员工、证书、培训记录、培训课程、培训实施、授权项目、人员授权的后端 Controller、DTO/VO、Mapper/Service 实现，并新增 `V1.26__shkb_hr_core.sql`。

迁移的前 12 张 HR 表以现网部署备份的只读 DDL 核对为依据；另补建部署代码已引用、但该备份未见的 `shkb_person_authorization_file`。迁移已在一次性本地 MySQL 中完成首次与重复执行验证，未触碰生产数据库。人员授权附件下载同时限制在应用上传目录内，避免由持久化 URL 逃逸到任意本地路径。

2026-08-17 已新增 `erp-backend/scripts/verify-hr-flow.ps1` 并在本地隔离库完成人事管理本地隔离验收：员工、证书、培训记录、培训课程、培训实施（含完成时参与人结果与员工培训记录同事务落库）、授权项目、人员授权七项功能的直连 API 与 Vite `/api` 代理读写流程、401/403/409 契约、导出和附件上传/列表/下载/删除及路径逃逸拒绝均通过，夹具与上传文件残留为 0。验收同时修复了员工附件/人员授权附件上传缺少父记录守卫、两个附件下载路径映射错误与错误信息泄露路径的问题。菜单/角色数据属于受控业务配置，未经业务确认不得作为自动生产迁移执行；HR 正式菜单/角色迁移仍为未完成项。

## 与可靠性矩阵的关系

现网范围确认不等于本地候选已达到 L5。人事模块目前为 L3：源码与版本化 schema 已补齐，且已在本地认证下完成七项功能的直连/Vite `/api` 写流程验收（`verify-hr-flow.ps1`，2026-08-17）；HR 菜单/角色业务配置、附件物理生命周期、浏览器人工验收和生产恢复副本验收仍缺。模块等级、迁移计划和验证证据继续以 `SHKB_MODULE_MATRIX.md` 为准。
